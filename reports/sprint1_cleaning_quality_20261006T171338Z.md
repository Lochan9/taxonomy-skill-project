## Method

- `clean_text`: one `html.unescape` of Greenhouse's entity-escaped HTML, then an HTML parser that decodes remaining entities, drops `script/style/iframe` content, turns block tags into paragraph breaks and `<li>` into `- ` bullets (nested lists indented).
- `text_hash`: SHA-256 of `clean_text` after NFKC, casefolding and whitespace collapsing. Empty text gets no hash, so empty rows are never "duplicates" of each other.
- Exact duplicates: rows sharing a `text_hash`; the first in config-board order then ascending job id is canonical. Titles are not used.
- Placeholders: title matches a general-interest / talent-pool pattern (dont_see_role, general_application, talent_pool, future_opportunities, open_application, expression_of_interest), or the description matches a narrow talent-pool phrase (join_talent_pool, resume_on_file). Rules are heuristic; flagged rows are kept for review.
- `source_language`: Greenhouse's employer-set `language` field, **not** detected language.
- `company_name` (standardized), `industry`, `industry_source`: from `config/boards.yaml`. `source_company_name`: the API's own `company_name`, unmodified.
- `cleaning_version`: `0.1.0`.
